# Render demo deployment (mock data)

[`render.yaml`](../render.yaml) deploys one free Render web service from [`Dockerfile.render`](../Dockerfile.render). The container builds the dashboard and serves it at `/` together with the API at `/api` (`backend/render_app.py`, the same security headers as `dashboard/nginx.conf` plus HSTS). It runs in `MOCK_DATA` mode: a SQLite demo database seeded with the demo accounts and classes when the service starts. No database server is needed.

## Deploy

1. Sign in at <https://render.com> with GitHub and allow access to this repository.
2. **New → Blueprint**, pick the repository and branch `main`.
3. When asked for `DEV_PASSWORD`, enter a strong password; it is the password for every demo account. Signing keys are generated by Render.
4. **Apply**. The first build takes a few minutes. Render then deploys automatically on every push to `main`.
5. Check `https://<service>.onrender.com/api/health/ready` returns `{"status":"ready"}`, then sign in as `teacher@focuslock.test`.

Phone app: `cd android; .\gradlew.bat :app:installDebug -PAPI_BASE_URL=https://<service>.onrender.com/api`

## Limits

- The free service sleeps after about 15 minutes without traffic. The next request takes roughly a minute to wake it, and the demo data is rebuilt then, so anything created earlier is gone.
- One process serves everyone, so teacher and students share the same demo data while it is awake.
- Demo only: the demo accounts are reachable by anyone with the URL and password. Never use real student data. For lasting data, remove `MOCK_DATA` and set `DATABASE_URL` to a managed PostgreSQL, then run the migrations as in [Vercel deployment](VERCEL_DEPLOYMENT.md).
