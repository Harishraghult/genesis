# Stage 5 optional Bluetooth evidence

An enrolled student with a confirmed check-in and active focus session may explicitly grant Bluetooth consent, then request a short-lived credential from the backend. The credential is held in memory only and expires within five minutes or at session end. No new credential is minted offline. The Android debug build requires `ENABLE_BLE_PRESENCE=true`, BLE advertising hardware and runtime `BLUETOOTH_ADVERTISE`/`BLUETOOTH_CONNECT` on Android 12+. It broadcasts a UUID with a fixed protocol prefix and a 12-byte HMAC fragment; no name or roll number is broadcast. The token changes every 15 seconds. Pause, Exit, expiry or process death stops advertising.

An authenticated receiver is bound to one course and room. The reference client in `backend/receiver/reference_receiver.py` scans and posts sightings with a timestamp, receiver ID and token. It needs `bleak` and `httpx` installed on the receiver host and the host OS's Bluetooth scanning/location permissions. A receiver inferring classroom location must **not** assert `neverForLocation`; the Android phone only advertises and does not scan. Receivers are provisioned by a restricted admin endpoint; the secret is returned once and only its digest is stored. The development fixture is explicitly simulated.

The backend rejects malformed tokens, stale timestamps, duplicate receiver/credential/slot combinations, expired credentials, inactive sessions, and a receiver assigned to the wrong course or room. It stores receiver, credential reference, slot and server receipt time, not raw tokens, RSSI, MAC addresses, packet contents or scan history. Sightings expire under the configured retention job. Consent withdrawal expires outstanding credentials. Receiver outages and unsupported phones show reduced evidence; teacher review/confirmation remains available. A sighting is only approximate evidence that a device was nearby. It does not prove the student was present, prevent relay attacks, or auto-mark anyone absent. Associating a student with a classroom is location-related information and is disclosed before opt-in.

`backend/tests/test_stage5.py` simulates receiver submissions; it does not validate BLE radio range, permission prompts, token rotation timing, collision behavior, receiver clock drift or hardware outages. Test those on actual phone and receiver hardware before use.
